# Inbox Page

Route `/inbox`. Composes the filter bar (`features/inbox-filters`), the vacancy list (`VacancyCard` from `entities/vacancy` + `VacancyActions` from `features/vacancy-actions` in its `actions` slot) and the Sources panel (`features/manage-sources`).

- `/inbox?source=<key>` (the link in the Telegram first-scan summary) starts with that source filter: read once on mount (`initialFilters`), the URL is not kept in sync. A key missing from the source lists still gets an option (see `features/inbox-filters`).
- Collapsible (backlog #9): the visible "Vacancies" h2 has a `SectionToggle` ("Hide Vacancies" / "Show Vacancies", `aria-expanded` + `aria-controls`) that hides the filters + list; `SourcesPanel` has its own. State from shared `useCollapsibleSection`, saved per browser in localStorage (`jobbi:inbox:listCollapsed`, "true" = collapsed; storage errors → expanded, no crash). Default expanded. Collapsed = the `hidden` attribute, not unmount, so filters, loaded pages, the Undo window and refreshes go on. A non-blank `?source=` opens a collapsed list expanded for that visit only and does NOT save it (the user's saved choice stays; next plain visit is collapsed again).
- The page owns `refreshKey`, the filter values and the source lists. `SourcesPanel`'s `onScanFinished` and `onSourceEdited` (a rename: cards show the new name) bump `refreshKey`; its `onSourcesChange` mirrors live + removed sources into the filter (no extra GET).
- A refresh reloads page 1 in the background (cards stay visible; a failed refresh keeps them). A filter change shows the loading state and reloads page 1 with the combined params.
- List: 20 per page, "Load more" appends and dedupes by id; a page that arrives after a refresh is dropped.
- `VacancyList` mounts `useVacancyActions` once, so unmounting the list (leaving the page) ends the Undo window. `removeItem` remembers the card's index and `restoreItem` puts it back there. A page-1 load that still lists a locally removed card (its request raced the dismiss) hides it and keeps its index; cards it no longer lists are forgotten, so their Undo does not insert (the next load shows them). Undo never inserts a card whose state the state filter excludes (restored as `seen` into a New list), and leaves the total as is.
- After a dismiss or a successful "Add to tracker" (`completeAdd`), focus goes to the Dismiss button of the card that takes its place, else the one before, else the page `h1` (`PageHeader titleRef`).
- After any local remove since the last page-1 load, "Load more" fetches the previous and the next server page in parallel and dedupes by id, because removals shift cards onto earlier pages. It also skips locally removed cards (a dismiss still in flight) and takes them off the server total.
- Empty state: "No vacancies yet…" with default filters, "No vacancies match these filters." otherwise.
