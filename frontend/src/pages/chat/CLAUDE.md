# Chat Page

Full-screen chat page for the AI assistant, scoped to a single application via route param `:id`. Composes chat entity APIs and chat-interface feature components. Handles SSE streaming, optimistic user messages, and clear-history confirmation.

- Optional router state `{draft}` (`ChatRouteState` from `entities/chat`, e.g. from "Add & tailor CV") pre-fills `ChatInput` but is never sent automatically. The page reads it once on mount, then replaces the history entry with `state: null` (same URL) so a reload or Back does not re-fill.
- Streaming: `event: reply` (rare, before `cards`) replaces the streamed text and `streamedTextRef`, so the reply moved into `messages` on `cards` is the saved text. The backend always sends `event: cards` before `done` (often `[]`, ignored). A non-empty `cards` moves the reply into `messages` at once under its persisted id (`cards[0].message_id`), so the history reload after `done` keeps the same React keys and a card decision started in between is not reset. A text-only reply is appended as a temp message on `done` until the reload replaces it. The reload result goes through `mergeCardStates`, so a card decided while it was in flight is not put back to Pending.
- Failed send: on `event: error` (or a network error) before the reply's `cards`, the backend has already deleted the user message, so the page drops the optimistic user bubble and puts the typed text back into `ChatInput` (`restored` state; a new `key` remounts the input with it as `draft`), next to the error toast. If tokens were streamed it still reloads the history, in case the server saved the reply before the connection broke.
