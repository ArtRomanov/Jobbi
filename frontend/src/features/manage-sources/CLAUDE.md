# Manage Sources Feature

Inbox "Sources" panel (`SourcesPanel`): add a Telegram channel (`@name` / `t.me/name`), a Greenhouse / Lever / Teamtailor / Ashby board link or any other http(s) page as a "Web page" (kind labels in `SOURCE_KIND_LABELS`), list watched sources with "Scanning…" / "Unavailable" + reason, remove a source (no confirm, Undo toast), and the "What are you looking for?" form (search description, pre-AI keywords + filter switch, "skipped in the last 24 hours" counter).

- Collapsible (backlog #9): a `SectionToggle` in the heading row ("Hide Sources" / "Show Sources") hides everything under the heading + subtitle. Saved per browser (`SOURCES_COLLAPSED_STORAGE_KEY` = `jobbi:inbox:sourcesCollapsed`, via shared `useCollapsibleSection`). Collapsed = the `hidden` attribute (stays mounted): add-form / preview / search-settings drafts survive, polling and `onSourcesChange` keep feeding the Inbox filter. The focus moves below only happen while it is expanded (the user acts inside it); `SourcesNotices` is not announced while hidden.
- State lives in `model/use-manage-sources.ts` (list, polling, remove), `model/use-deferred-remove.ts` (Remove's Undo window) and `model/use-add-source.ts` (input + add flow). Add errors are shown inline under the input (`getErrorMessage` — the backend's 400/409 `detail` text is user-facing); remove errors go to a toast.
- The add form stays disabled until the initial list loads, so a late GET can't overwrite a just-added source.
- Focus: after Add (success or error) it returns to the input. After Remove (the row hides at once) the target is picked once the list without the row is committed (`removeFocus` effect in `SourcesPanel`), against the CURRENT visible list and the full-list order at click (`pickFocusAfterRemove`): the next row's Remove (it slides into the removed row's place, maybe from the next page), else the previous row's (the clamp may show the previous page; `revealSource` + `focusRemoveId` focus it after that page renders), else the input; rows already hidden by other pending removes are skipped. Nothing moves if focus was not on that Remove (or `<body>`) when it was pressed. After Undo: `revealSource(id)` opens the restored row's page and `focusRemoveId` focuses its Remove.
- Remove with Undo (backlog #10), client-side only (`useDeferredRemove`, no backend change): Remove hides the row at once (`pendingIds`; the hook returns `sources` without them) and shows an info toast "Source removed" + "Undo" (`REMOVE_UNDO_WINDOW_MS` 5 s, the shared toast pauses on hover / focus, so the Undo button is keyboard reachable). Nothing is sent until the toast ends by its own timer (shared `ToastOptions.onTimeout`); then ONE `DELETE` goes (`sendRemove`) and the row stays hidden until it settles (so there is no per-row "removing" state). Success / 404 (already gone) → dropped from the list + `refreshRemovedSources`; other errors → row shows again + error toast. Undo = un-hide, no request. Each Remove has its own toast + pending delete. A hidden row stays in the list state, so polls (`mergePolledSources`) keep updating it and cannot resurrect it, Undo shows its current status, and `onSourcesChange` keeps it live for the Inbox filter until the DELETE succeeds (only then "(removed)"). Pending deletes are sent at once (toasts closed) on unmount (leaving the Inbox), on `pagehide` (with fetch `keepalive`, so a closed / reloaded tab still sends it), before Add / Re-check / preview Save / "Add the board" (`useAddSource`'s `beforeAdd` = `flushRemovals`, awaited) and before an Edit-dialog link / pattern change or Re-check is checked (`onBeforeLinkChange` → `useEditSource`'s `beforeLinkChange`): re-adding or re-linking a source during its Undo window is then not a 409 duplicate, and a hidden row never counts toward the 50-source limit. The DELETE carries the auth token captured at Remove time (`getAuthToken` → `RequestOptions.authToken`), because logout clears the token before the panel unmounts and flushes (the backend's logout does not revoke the token). Known limit: the `pagehide` DELETE is a keepalive request that needs a CORS preflight, which some browsers drop, and a tab the browser discards (no `pagehide`) never sends it, so in those cases the source stays watched.
- Pagination (backlog #16): client-side, `SOURCES_PAGE_SIZE` = 7 per page over the one GET (≤ 50 sources). `model/use-source-pages.ts` pages the VISIBLE list (rows pending removal left out; pure math in `lib/paging.ts`); paging is view-only, so `onSourcesChange` (Inbox filter, the full list), polling merges and remove/edit all work on the whole list and rows on every page stay current. The page is adjusted during render: clamped when the list shrinks (removing the last row of the last page shows the previous page) and `revealSource(id)` jumps to a page once the id is in the list. Add appends at the end, so `SourcesPanel` wraps `appendSource` to reveal the new row (focus still returns to the input). Edit replaces in place, so the row stays on its page. `SourcesPager` (`<nav aria-label="Sources pages">`, Previous / "Page N" buttons with `aria-current="page"` / Next) renders only with > 7 sources; focus stays on the pressed control (Previous / Next are `keepFocusable`, aria-disabled at the ends). No in-panel search/filter exists; a future one passes its filtered list to `useSourcePages` and calls `setPage(0)` on a query change.
- The backend checks a channel live (up to ~10 s), so the input is read-only and "Add" shows loading while a request runs; one ref in `useAddSource` blocks overlapping submit / re-check / save requests.
- Add flow: Add always calls `previewVacancySource` first. Kind ≠ `web` → `addVacancySource({input})` at once (no preview UI). Kind `web` → inline `SourcePreview` under the form ("Found N vacancies", ≤ 5 titles in site order, "Job link contains" + Re-check (Enter in that field re-checks and keeps focus there; a Re-check click refocuses Re-check; a failed Save refocuses Save), optional Name with the default name as placeholder, Save / Cancel). First-preview errors go under the input; re-check / save errors inside the preview. Save sends the input the preview was made for, plus pattern and name (blank → null, zod in `model/schemas.ts`), then clears the input, closes the preview and focuses the input. Cancel keeps the input and focuses it. Typing in the input closes an open preview (stale). Each new Add re-mounts the preview (`key = preview.id`) and focuses its heading; the count + titles block is `aria-live="polite"`.
- ATS hint: when the preview has `ats_hint`, `AtsHint` shows "This page uses <label> — add the board instead for full job texts and dates", a muted plain-text "Board: <input without scheme>" (so a hostile page cannot hide which board gets added) + "Add the board" (accessible name "Add the board <board>"). It calls `addBoard(ats_hint.input)` (non-web path, same busy ref, action `"board"`): success appends the row, clears the input, closes the preview and focuses the input; errors show inside the preview and focus returns to the button. Save still works. The hint only renders when `onAddBoard` is passed. A preview with `found_count: 0` (backend sends it only with a hint) shows the muted `PREVIEW_NO_VACANCIES_TEXT` as the heading, no titles, Save disabled; Re-check and the hint still work.
- `SourcePreview` is UI-only (drafts + validation inside, requests via `onRecheck` / `onSave` props) so the Edit dialog reuses it (there it keeps `focusOnMount`: the form's focused Save button is hidden when the preview appears, so the heading takes focus).
- Hint under the add input, always visible: "Sort the page by newest first before copying the link" (linked with `aria-describedby`).
- Search settings: `SearchSettingsForm` + `model/use-search-settings-form.ts`. Saved settings come from the same GET and live in `useManageSources` (`settings`, null until loaded); the form is keyed on load so its drafts start from them and it stays disabled until then. Save PATCHes `description`, `keywords` and `keyword_filter` in ONE request and then resets the drafts to the server-normalized values (keywords come back lowercased / de-duped); errors inline under Save (any edit clears them), success toast "Saved"; focus returns to Save. Save is off until the drafts differ from the last saved settings (`isDirty`, `lib/search-settings-changes.ts` mirrors the server's normalization: description trimmed with blank = none, keywords trimmed / whitespace-collapsed / lowercased / de-duped, order matters; "whitespace" is exactly Python's `str.isspace()` set (`PY_WHITESPACE`), not JS `\s` / `trim()`, which differ on U+FEFF, U+001C–U+001F and U+0085; the PATCH's blank → null check uses the same `normalizeDescription`, the non-blank description is sent raw); once loaded it is `keepFocusable` (aria-disabled), before load truly disabled. `initialSettings` is updated by the parent after each save, so it is always the latest saved value.
- The "Describe what you're looking for…" hint follows the *saved* description, so it does not hide while the user types an unsaved draft.
- Description: `maxLength` 500 stops typing and the setter also cuts pasted text.
- Keywords: shared `ChipInput` (Enter or a comma adds; blur adds; Backspace on empty removes the last; case-insensitive duplicates ignored; chips keep the typed case until the server normalizes them). Client limits mirror the server's (`KEYWORDS_MAX_COUNT` 50 → input disabled + "You can add up to 50 keywords"; `KEYWORD_MAX_LENGTH` 64 → longer text is cut); the server's 400 `detail` is still shown. Hint (aria-describedby): a keyword also matches longer words ("фронт" finds "фронтенд"), "front end" also finds "front-end".
- `KeywordFilterSwitch` ("Only send posts with these words to the AI" = `keyword_filter`): checkbox with `role="switch"`, help text says skipped posts are deleted for good, off / no keywords = every post goes to the AI, forwarded posts are never skipped. "Skipped by the filter in the last 24 hours: N" comes from `status.filtered_last_24h` (updates with polls; hidden until loaded).
- Each source shows "Scanning…" or "Last checked <formatTimeAgo>" (nothing when never checked). A web page not checked since it was saved (`last_checked_at` null or equal to `watching_since`) shows "Watching since <formatTimeAgo>" instead (`getCheckedLabel`). Under it, a muted "Waiting for AI: N" (`getPendingLabel`) when `pending_count` > 0 (backlog #19).
- Polling: after the initial load, ONE setTimeout chain in `useManageSources` re-fetches GET /vacancy-sources (requests never overlap): every 5 s while any source is scanning, else every 60 s (`getPollInterval`). The 60 s refresh only runs while `document.visibilityState === "visible"`; when hidden the chain stops and a `visibilitychange` back to visible resumes it (immediately if a full interval has passed). Cleared on unmount. Polls only update status fields (incl. `watching_since`, `editable` and `pending_count`) of sources already in the local list (`mergePolledSources`), so a poll can't undo a concurrent add/remove or touch the settings drafts. Poll-merge guard: ids added or edited while a poll's GET is in flight go into `editedSinceRef` (cleared when each GET starts); that poll skips them, so its older copy can't overwrite a just-saved row (e.g. bring back the old name or `editable`). When a source goes scanning → not scanning, `SourcesPanel`'s `onScanFinished` runs and `notifyVacanciesChanged()` (from `entities/vacancy`) fires.
- `onSourcesChange(sources, removedSources)` feeds the Inbox source filter (no second GET). `removed_sources` comes from the load and polls; after a removal it is re-fetched in the background (latest response wins).
- Status notices (`SourcesNotices`, above the list): `status` from the same GET/polls; "Daily limit reached — N posts are waiting" ("1 post is waiting") and the AI-outage text, both may show. The `role="status"` region is always mounted so notices added by a poll are announced politely.
- Unavailable source: tinted row + "Unavailable — <last_error>" (fallback "Could not reach the source"); Remove stays enabled. The backend decides the 24 h threshold.
- Edit: every row has "Edit" (accessible name "Edit <display_name>") before Remove; disabled while a first-scan attempt runs (`editable: false`, `title` + visually hidden `aria-describedby` "Scanning — try again in a moment"); a poll re-enables it. It opens `EditSourceDialog` (state per row in `SourceListItem`, mounted only while open). Fields (react-hook-form + `editSourceSchema`): Name (trimmed, ≤ 100, no `maxLength` so pasted text is reported; blank → `null` = default name; starts with `display_name` when `name_is_custom`, else empty with `display_name` as placeholder), Link (required, prefilled by `getSourceLink`: web `url`, `@handle` for Telegram, board link for Greenhouse / Lever / Teamtailor / Ashby, handle = `key` after "kind:"), and for web "Job link contains". Save is off (`keepFocusable`, Enter in a field sends nothing too) until a field differs from its starting value after trimming (`lib/edit-source-changes.ts`, mirrors `editSourceSchema`; not RHF `isDirty`, so spaces alone are no change).
- Edit save (`useEditSource`, one busy ref): link and pattern unchanged → `PATCH {name}`. Changed → `previewVacancySource({input, job_link_contains, source_id})` (`source_id` keeps the edited source out of duplicate / 50-source checks). Kind `web` → the form is *hidden* (not unmounted, drafts kept) and `SourcePreview` shows "Link: <url>" + found N / titles / Re-check, seeded with the pattern and name drafts; its Save PATCHes `{input, job_link_contains, name}` and is off (`keepFocusable`, Enter sends nothing) while the preview's link + pattern + name drafts equal the dialog's starting values (`hasChanges` prop → `hasEditSourceChanges`; a changed link alone keeps it on; the add flow passes no `hasChanges`, so its Save is unaffected), its Cancel goes back to the form and focuses Link. Other kinds → `PATCH {input, name}` at once. Errors inline (form or preview; incl. 409 "This source is being scanned — try again in a moment"); Escape/backdrop blocked while any request runs.
- Edit success: `replaceSource(previousId, source)` puts the server's copy in the edited row's place. Web edits keep the id. Other kinds (or a kind change) come back with a NEW id (the old source is gone): the new row replaces the old, `refreshRemovedSources` runs so "<old name> (removed)" appears in the Inbox filter, and `SourcesPanel` focuses the new row's Edit (focusable even while a first scan blocks it: `aria-disabled` + reason) since the Modal's opener is gone. Then `onSourceEdited` fires (the Inbox bumps `refreshKey`).
