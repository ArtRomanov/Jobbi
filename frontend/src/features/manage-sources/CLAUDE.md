# Manage Sources Feature

Inbox "Sources" panel (`SourcesPanel`): add a Telegram channel (`@name` / `t.me/name`), a Greenhouse / Lever / Teamtailor board link or any other http(s) page as a "Web page" (kind labels in `SOURCE_KIND_LABELS`), list watched sources with "Scanning…" / "Unavailable" + reason, remove a source (no confirm), and the "What are you looking for?" form (search description + exclude words).

- State lives in `model/use-manage-sources.ts` (list, polling, remove) and `model/use-add-source.ts` (input + add flow). Add errors are shown inline under the input (`getErrorMessage` — the backend's 400/409 `detail` text is user-facing); remove errors go to a toast.
- The add form stays disabled until the initial list loads, so a late GET can't overwrite a just-added source.
- Focus: after Add (success or error) it returns to the input; after Remove it moves to the next Remove button, else the previous one, else the input (`lib/helpers.ts`).
- The backend checks a channel live (up to ~10 s), so the input is read-only and "Add" shows loading while a request runs; one ref in `useAddSource` blocks overlapping submit / re-check / save requests.
- Add flow: Add always calls `previewVacancySource` first. Kind ≠ `web` → `addVacancySource({input})` at once (no preview UI). Kind `web` → inline `SourcePreview` under the form ("Found N vacancies", ≤ 5 titles in site order, "Job link contains" + Re-check (Enter in that field re-checks and keeps focus there; a Re-check click refocuses Re-check; a failed Save refocuses Save), optional Name with the default name as placeholder, Save / Cancel). First-preview errors go under the input; re-check / save errors inside the preview. Save sends the input the preview was made for, plus pattern and name (blank → null, zod in `model/schemas.ts`), then clears the input, closes the preview and focuses the input. Cancel keeps the input and focuses it. Typing in the input closes an open preview (stale). Each new Add re-mounts the preview (`key = preview.id`) and focuses its heading; the count + titles block is `aria-live="polite"`.
- ATS hint: when the preview has `ats_hint`, `AtsHint` shows "This page uses <label> — add the board instead for full job texts and dates" + "Add the board". It calls `addBoard(ats_hint.input)` (non-web path, same busy ref, action `"board"`): success appends the row, clears the input, closes the preview and focuses the input; errors show inside the preview and focus returns to the button. Save still works. The hint only renders when `onAddBoard` is passed.
- `SourcePreview` is UI-only (drafts + validation inside, requests via `onRecheck` / `onSave` props) so the Edit dialog (Slice 6) can reuse it; `focusOnMount={false}` when a dialog manages focus.
- Hint under the add input, always visible: "Sort the page by newest first before copying the link" (linked with `aria-describedby`).
- Search settings: `SearchSettingsForm` + `model/use-search-settings-form.ts`. Saved settings come from the same GET and live in `useManageSources` (`settings`, null until loaded); the form is keyed on load so its drafts start from them and it stays disabled until then. Save PATCHes both fields and then shows the server-normalized values; errors inline under Save, success toast "Saved"; focus returns to Save.
- The "Describe what you're looking for…" hint follows the *saved* description, so it does not hide while the user types an unsaved draft.
- Description: `maxLength` 500 stops typing and the setter also cuts pasted text. Exclude words use `ChipInput` from `@/shared/ui` (50 max, 64 chars each).
- Each source shows "Scanning…" or "Last checked <formatTimeAgo>" (nothing when never checked). A web page not checked since it was saved (`last_checked_at` null or equal to `watching_since`) shows "Watching since <formatTimeAgo>" instead (`getCheckedLabel`).
- Polling: after the initial load, ONE setTimeout chain in `useManageSources` re-fetches GET /vacancy-sources (requests never overlap): every 5 s while any source is scanning, else every 60 s (`getPollInterval`). The 60 s refresh only runs while `document.visibilityState === "visible"`; when hidden the chain stops and a `visibilitychange` back to visible resumes it (immediately if a full interval has passed). Cleared on unmount. Polls only update status fields (incl. `watching_since`) of sources already in the local list (`mergePolledSources`), so a poll can't undo a concurrent add/remove or touch the settings drafts. When a source goes scanning → not scanning, `SourcesPanel`'s `onScanFinished` runs and `notifyVacanciesChanged()` (from `entities/vacancy`) fires.
- `onSourcesChange(sources, removedSources)` feeds the Inbox source filter (no second GET). `removed_sources` comes from the load and polls; after a removal it is re-fetched in the background (latest response wins).
- Status notices (`SourcesNotices`, above the list): `status` from the same GET/polls; "Daily limit reached — N posts are waiting" ("1 post is waiting") and the AI-outage text, both may show. The `role="status"` region is always mounted so notices added by a poll are announced politely.
- Unavailable source: tinted row + "Unavailable — <last_error>" (fallback "Could not reach the source"); Remove stays enabled. The backend decides the 24 h threshold.
