# Chat Interface Feature

User-facing chat UI components for the AI assistant. Contains MessageBubble, ChatInput, QuickActionBar, and ChatWindow. Quick-action templates live in lib/constants.ts. Composed at the page level by pages/chat.

- **CV change cards** (spec 011 §2.7): `ui/cv-change-card.tsx` renders one `ChangeCard` titled "CV text — change N" (N = position in its message, passed by `card-list`; buttons are named "Accept change N" / "Reject change N"; after a decision resolves focus moves to the title (`tabIndex={-1}`) and the always-mounted `role="status"` wrapper announces the new badge) (pieces: `card-body`, `card-state-badge`, `diff-lines-view`, `diff-line`; styles and markers in `lib/card-styles.ts`). Replace → "Before"/"After" columns from `diffLines` (`lib/build-diff-rows.ts`); insert → only the added lines, labelled by `lib/card-labels.ts`; remove → only the removed lines, "Removed"; replace_all (backlog #34) → titled "Whole CV — change N", `ui/whole-cv-diff.tsx` shows one unified diff per changed / moved / added / removed `## ` section ("moved": same text, new order — Accept applies the order, so it is shown) ("Summary — changed"; the text before the first `## ` is "Header"), unchanged sections collapsed in a `<details>` at the end (`lib/build-section-diff.ts`: sections matched by heading, case-blind; blank lines at a section's edges do not count). Accept / Reject / Stale work as for any card (Stale: the CV changed since the card was made). Removed/added lines differ by colour **and** by a `−`/`+` marker, `<del>`/`<ins>` and a screen-reader prefix.
- `ChatWindow` renders each message's `cards` right under its bubble (`ui/card-list.tsx`). A reply that is only a tool call has empty `content`: then only its cards render, no empty bubble. Card updates go up through `onCardUpdated`; the page swaps them in with `replaceCardInMessages`.
- `model/use-card-decision.ts`: a successful Accept toasts "Change applied to your CV" (`CARD_ACCEPTED_MESSAGE`; needs a `ToastProvider`); Reject has no toast. One request per card (cards are decided independently; both buttons disabled while it runs). Errors map from `{"detail": "<CODE>"}` in `lib/card-error-message.ts`: `CARD_STALE` (the server first tries to re-aim a card whose passage changed, e.g. after an earlier card edited the same paragraph; Stale only when that is unclear) also marks the card Stale (Accept disabled, Reject still works); `CARD_DECIDED` re-reads the card from `GET /chat` and shows its real state without an error; `CV_BUSY` (the CV kept changing during the Accept), 5xx, network and unknown codes → the generic text, card stays Pending.
- **Outdated cards**: only the newest message's cards can be decided. `ChatWindow` passes `outdated` (message id ≠ last message id) through `CardList` to `CvChangeCard`: no buttons, and a Pending card shows the muted `CARD_OUTDATED_LABEL` "Outdated — newer messages below" (Accepted/Rejected/Stale keep their badges). The page appends the optimistic user message on send, so older cards go outdated at once, while the reply streams. The server enforces it (409 `CARD_OUTDATED`, e.g. a second tab): `use-card-decision` shows a toast, the card stays as it is.
- `lib/merge-card-states.ts`: `mergeCardStates(local, fresh)` keeps a local decided/stale card over a server copy that still says pending (a history reload that started before the decision).
- **Card warning** (backlog #27): a non-null `card.warning` shows as `ui/card-warning.tsx` ("Check before accepting: …", warning colours) under the diff; the Accept button's `aria-describedby` points at it. Not a live region (a history load would announce every card). Accept stays enabled: the user decides.
- **Quick actions** (`lib/constants.ts`): `requiresCv` disables an action until a CV is linked; `hiddenWithoutCv` hides it ("Structure my CV", backlog #27). `QuickActionBar`'s `disabled` (the page passes `isSending`) disables every action while a message sends/streams. No UI language switch exists, so the texts are English.
- **Assistant Markdown**: `ui/assistant-markdown.tsx` lexes assistant replies with `marked` and walks the tokens into React elements (no HTML string, no `dangerouslySetInnerHTML`). Raw `html` tokens, tables, images show as typed text; links only for http/https/mailto (`isSafeCvLinkUrl`), new tab. Headings start at `<h3>` (the page owns `<h1>`), sized for a bubble (`lib/chat-markdown-styles.ts`). The streaming cursor goes inside the last paragraph/heading. User messages stay plain `pre-wrap` text. Separate from the CV renderer on purpose: the CV model shows code/quotes/rules raw.
