# Chat Entity

Domain entity for AI chat messages scoped to a job application. Provides the ChatMessage type (re-exported from generated schema) and API functions: getChatHistory, clearChatHistory, and sendChatMessage (SSE streaming via raw fetch).

- `ChatRouteState` / `getChatDraft(location.state)`: the `{draft}` router-state contract for opening the chat with an unsent, pre-filled message.
- Change cards (spec 011 slice 7): `ChangeCard` = generated `ChangeCardRead` (`decided_at` is null while pending or stale) plus `warning: string | null` (backlog #27), declared by hand in `model/types.ts` because `schema.d.ts` is generated locally and not committed; `ChatMessage.cards` uses that type. `parseCardsEvent` reads a missing `warning` as null. `ChatMessageRead.cards` is always present (`[]` for user messages and replies without edits), so locally built messages must pass `cards: []`. `acceptChangeCard` / `rejectChangeCard` call `POST …/chat/cards/{id}/accept|reject`.
- `sendChatMessage(appId, content, { onToken, onReply, onCards, onDone, onError })`: frame payloads are JSON — `token` `{"text"}`, `reply` `{"text"}` (at most once, before `cards`: the whole reply as saved, which replaces the streamed text — sent when the fact guard marked an item it left out), `error` `{"detail"}` (decoded by `readField`), `cards` a `ChangeCard[]` sent before `done` on every reply (often `[]`), parsed by `parseCardsEvent`, which drops malformed entries instead of failing the stream.
