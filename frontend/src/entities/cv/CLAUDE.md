# CV Entity

CV types (aliases of the generated OpenAPI schemas), CRUD API functions, and the CV text formatting shared by the preview and the PDF.

- `uploadCv` is extract-only (`CvUploadResult` = `CvExtractRead`: `{name, content, truncated}`); it creates nothing. `CvCreate` / `CvUpdate` carry `is_base` (spec 011 slice 9).

- `parseCvMarkdown(content)` (`lib/cv-markdown.ts`) is the ONE place CV Markdown is parsed: a `marked` lexer (GFM, `breaks: true`) walked into a renderer-neutral block model (`CvBlock` / `CvInline`). Supported: heading 1–4, paragraph, bold, italic, bullet/ordered lists, links, line breaks. Everything else (tables, HTML, images, code, quotes, rules, heading 5+) becomes a `raw` block / text with the token's `raw`, i.e. shown exactly as typed. `features/cv-pdf` renders the same model — add formatting here, never in one renderer only.
- Reference definitions (`[1]: https://…`) are not printed. Display text decodes only `&amp; &lt; &gt; &quot;` and numeric entities; `raw` text is kept as typed.
- Links: only `isSafeCvLinkUrl` (http, https, mailto) becomes a `link` node; any other link is kept as its typed text. The check runs on the href as typed, never entity-decoded (`&#106;avascript:` stays unsafe). Renderers re-check it.
- Designed layout (backlog #11, spec 011 §2.9): `buildCvLayout(markdown)` (`lib/cv-layout.ts`) regroups the parser's blocks into header (first `#` + title line + contacts), sections, `###` entries and their `####` projects (backlog #27: `CvLayoutEntry.projects`, each a `CvLayoutProject` with its own dates and blocks; a `####` with no `###` above it in the section is a lone `project` item) (date line → title row via `isDateRangeLine`, EN/RU; paragraphs before the first list = muted context). Layout only: it never adds, removes or reorders words; contact separators are shown as " · " (`cv-layout.test.ts` has seeded property tests on the layout and on the rendered HTML text, word boundaries included). Header title + contacts are taken only when the contacts hold a real sign (email, phone, link/URL; a year range like "2016 - 2024" is not a phone); otherwise the name stands alone. A date line's note after the range is ≤ 20 chars (`MAX_DATE_TAIL_LENGTH`). The title/dates separator is kept as `datesSeparator` and rendered visually hidden (`cv-hidden-text`) so the text never reads "EngineerJan". ATS reading order: the dates sit on their own line under the title and bullet dots are floats, not `position:absolute` — right-aligned dates and positioned dots come out of order in PDF text extractors (guarded in `cv-html-export.test.ts`). `CvLayoutView` renders it (React only; `isEmbedded` shifts headings to h2–h5 and opens links in a new tab), styled by `CV_LAYOUT_CSS` (scoped `.cv-doc`, our constant CSS — never CV text). `CvLayoutPreview` = editor preview (fonts via `?url` from `lib/cv-font-urls.ts`); `features/cv-html-export` renders the same view to the downloaded file. Font list in `lib/cv-layout-fonts.ts`.
- `CvTextPreview` (old plain preview) is no longer used by the editor; it stays as the reference of the react-pdf parity test. It renders React elements only (no `dangerouslySetInnerHTML`); headings 1–3 map to `h2`–`h4` because the host page owns the `h1`.
- Base CV and tailored copies (spec 011 §2.4–2.6): `groupCvs` splits a list into `base` / `own` (base first) / `tailored`, keyed on `is_base` and `kind` (a base always counts as own); the server already orders the list this way, the UI regroups defensively. `buildCvSelectChoices` gives every CV `<select>` the same shape: own CVs first with the base labelled "(base)", then a "Tailored copies" optgroup. `CvTailoredFor` renders "<Company> — <Role>" linking to `ROUTES.dashboardApplication`, or "Application deleted".
